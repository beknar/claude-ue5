- **Shell:** Windows PowerShell 5.1. When writing a .py file from PowerShell, use `[IO.File]::WriteAllText(path, text, (New-Object Text.UTF8Encoding $false))`; `Set-Content -Encoding utf8` adds a BOM that the editor's Python rejects. In an array literal the comma binds tighter than `+`: `@('a', 'b' + $x)` is `('a', 'b') + $x`, so a find / replace pair built that way silently replaces with the wrong text (it dropped a line from two files): patch files with a Python script that asserts each match.
- **Python in the editor:** `python pipeline\blender_numpy\ue_exec.py <script.py> [args]`, where the args become `sys.argv`; `-c "code"` runs a snippet and `--ping` checks for an editor. The editor needs PythonScriptPlugin remote execution (enabled in `Config/DefaultEngine.ini`).
- **MCP:** an `unreal-mcp` server (UE ModelContextProtocol plugin, `http://127.0.0.1:8765/mcp`) is configured in `.mcp.json`.

## Conventions

- **Script names:** editor scripts are `pipeline/unreal/NNN_name.py`, numbered in build order. Each starts with a docstring giving its purpose and arguments. New stages get the next free number in their range (see README).
- **One-off probes:** keep them out of `pipeline/` (use a scratch directory) unless they become a pipeline stage.
- **Idempotent:** scripts delete what they previously generated (by tag, label or asset path) and rebuild it. Spawned actors are tagged:
  - `castle_gen`: `340` (doors, floors, containers)
  - `castle_furn`: `380` (furniture)
  - sf-city-level: `sfc_road` (`703`), `sfc_struct` (`706`), `sfc_start` (`707`), `sfc_safety` (`708` barrier walls)
- **Cinematic copies:** each level has a `*_Cine` copy. Demo characters run on the Level Sequence clock (`SeqTime`/`DemoStartTime`), so Simulate (game time) and Movie Render Queue renders match.
- **Coordinates:**
  - UE = Blender (x, −y, z) for FBX round trips.
  - The furniture kit's front is UE +Y.
  - Kit sizes are in cm; the Blender scene uses `scale_length` 0.01.
- **End of big scripts:** delete the module globals and run `gc.collect()`. Lingering actor references caused python311 access violations on the next PIE start or map load. `ue_exec.py` now runs each script in a fresh namespace and clears it afterwards, also when the script raises (an exception's traceback otherwise keeps its actors alive). Scripts that leave a tick callback running must set `__keep__ = True` (their functions still need their globals) and drop their actor references when the callback finishes.
- **C++ module** (`claude_ue5/Source/claude_ue5`, random_level's town generator): build with `pipeline\build_cpp.ps1` while the editor is closed, then relaunch. Unity builds merge the .cpp files: give file-local helpers and constants a module prefix (`IVPickSign`, `RDPickSign`, `IVCyan`, `SSGreen`), or adding a file can make two of them collide. No .NET Framework SDK is installed, so the script points UnrealBuildTool at a stand-in NETFXSDK (UE_SDKS_ROOT) for that build only. Python sees UPROPERTY bools without the `b` prefix (`bCollision` -> `collision`).
- **random_level:** the town is generated by `ARTTownGenerator` (start square built in the editor by `752`, runtime cells never saved). Re-run `752` after changing templates or generator code. Docks building maps (`LI_Building_*`) cannot be opened while random_level is loaded (they are its level instances); `750`/`750b` open a scratch level first. `753` (generation indicator) rebuilds its materials in place and must be re-run on both random_level and random_level_Cine (each level's generator stores RevealDuration). In random_level_Cine the generator follows `Demo_RL_Fem5` (`TrackedActor`, fixed session seed).
- **random_dungeon_level:** C++ `ARDDungeonGenerator` / `ARDSection` (`Source/claude_ue5/RD`). Content is data: `770` fills the generator's `Pieces` map (each mesh normalised by `Adjust` to the dungeon frame: front +X, footprint centred, floor z 0) and the furnishing code places pieces by name, so a missing piece is skipped silently (check `770`'s piece list). Re-run `770` after C++ layout/furnishing changes (the start section is saved; play rebuilds only its doors, containers, monsters and map data from the same seed). Runtime sections are built over several frames (`FrameBudgetMs`). Every container must be openable (body + moving part); don't add closed barrels/crates/vases as static props. random_dungeon_level_Cine (`773`-`775`): the generator follows `Demo_RD_Fem5` (`TrackedActor`, fixed seed) and opens doors in front of her (`TrackedAutoDoorDistance`); monsters don't block her (`bMonstersBlockPawns` off).
- **random_dungeoncombat_level:** a Save As copy of random_dungeon_level whose generator has `bCombat` and `bStylizedMap` on (`790`-`799`); the two levels share the C++ and `BP_RD_GameMode`, so anything new must stay behind those flags.
  - The player's side is `URDCombatComponent`, which the generator puts on the player pawn in play (the pawn is a Blueprint). Attacks are dynamic montages on her AnimBP's `DefaultSlot` (`PlaySlotAnimationAsDynamicMontage`); weapons are data on the generator (`Weapons`, from `790`'s weapons.json via `791`).
  - Her skeleton has no finger or hand-end bones (`righthand_end` is a clip track, not a bone: its socket location is the origin). Grips are computed from the reference pose (T-pose, palms down).
  - A monster's hit points and damage = the player's hit points / her average blow x the tier of its section (`StartMonster*`, `RuntimeMonster*`) x its kind's factor / the weighted mean of the factors. With `bCombat` the generator gives exactly `MonsterCoverage` of the rooms a monster (the old level flips a coin per room).
  - `ARDDungeonGenerator.RestartPlay(seed)` puts the dungeon back to its start with a fixed session seed (demo reel, tests). A step function of a generator-style test that never yields is not a generator: `yield from` on it fails.
  - A PowerShell here-string containing `(RM);` trips the permission layer's Remove-Item check: write such patches with the Write tool.
  - Blood (`URDBloodComponent`, made by the generator in play), the wounds and the sounds are data on the generator (`798`, `797`); a level without them is silent and bloodless. Sound and blood have random streams of their own (`SoundR`, the component's, a monster's `SR`): they must never draw from the streams the play uses, or a reel stops repeating.
  - Wounds: an overlay material instance per monster (`M_RDC_Wounds`, `SetOverlayMaterial`), its wounds stored in the mesh's reference pose (the material compares them with the pre-skinned position). The wound vertex is found by skinning a spread of LOD vertices on the CPU (`GetSkinnedVertexPosition`; the vertex buffers are readable in the editor; a packaged game keeps them unless `r.FreeSkeletalMeshBuffers` is set, which was not tried), with the nearest bone as the fallback.
  - This project has Substrate on: a pack material written for the old shading models may not compile (the engine then draws the default material without an error on screen: RealisticBlood's decals were pale squares; the log says `Failed to compile ... Default Material will be used`). A deferred decal needs a Substrate blend mode (`BLEND_TRANSLUCENT_GREY_TRANSMITTANCE`).
  - Building a material from Python logs `Failed to compile` for every half-built state (each `set_editor_property` on a node recompiles); only one after the final `recompile_material` is real (`798` logs a marker line before it). `get_statistics(...).num_pixel_shader_instructions > 0` does not prove the material compiled.
  - Sound: `Sounds` maps an occasion to a set (`sounds.json` -> `rdc_sound_prep.py` -> `797`). Placed sets are played at a location with an attenuation object made at run time per (inner radius, falloff); the listener's attenuation point is the pawn. The generator sets the audio listener itself every tick: the viewport does not do it for a play-in-editor window without focus.
  - Nobody hears a test: counting `PlaySound` calls proved nothing about what comes out. `799_rdc_sound_test.ps1` (the game with `-RDSoundTest=<dir>`) records the device's output with sounds at known places and `rdc_sound_check.py` measures it: do that after touching attenuation or spatialisation. A play-in-editor or game window without focus is silent (`FApp::SetUnfocusedVolumeMultiplier`; the test sets it).
  - Movie Render Queue sound: the job needs a `MoviePipelineWaveOutput` setting and the editor started with `-deterministicaudio`. That non-realtime audio device loses every *spatialised* source (measured with test sounds from all sides: only flat and non-spatialised ones are in the `.wav`), so under `-deterministicaudio` the generator plays its placed sounds with the distance falloff but without direction (`bSpatializeSounds`, `AreSoundsSpatialized`). Run tests and normal play in an editor started without the switch.
  - A monster asked the door's *progress* before pushing it (`GetDoorOpenAlpha < 0.01`): at more than about 140 ticks a second (the render queue's sub-steps, a fast machine) the leaf had not moved that far by the next tick and the monster toggled it for ever. Ask for the state a thing is heading to (`IsTargetOpen`), not how far it has got.
- **random_isometric_village_level:** C++ `AIVVillageGenerator` / `AIVSection` / `AIVVillager` / `AIVPlayerController` / `AIVHUD` (`Source/claude_ue5/IV`).
  - The plan (ring streets, lanes, main roads, building sites) is a pure function of the plan seeds, so sections generated in any order continue the same village. Rings 0..4 and the bands between them use `StartSeed` (everything the start section touches); beyond that the session seed. A site's place and footprint come from the plan seed, what is built on it from the section seed.
  - Lane angles are not normalised: measure a block with `AngleSpan`, never with `A1 < A0`.
  - Content is data, as in the dungeon: `780` fills `Pieces` (House Forge kit pieces get explicit `Adjust` transforms: walls centred on their segment with the outside on +X, roofs cell-centred with the eave on +X); a missing piece is skipped silently. Re-run `780` after C++ plan / furnishing changes; it must report 0 unreachable doors / containers.
  - Each house keeps its roof, each of its four walls and each corner post in ISM components of their own (tags `IVG_<building>_<group>`: 0 roof, 1-4 the +X / -X / +Y / -Y wall, 5-8 corners). While she is inside, the roof and the walls facing the camera *as the view is turned now* are hidden (they still cast shadows and collide); its lights (tags `IVF_<building>`) are on only then. Changing the groups means re-running `780` and `783` (the saved start sections carry the tags).
  - The view turns (Q / E, `ViewYawOffset`), so anything decided at build time uses `ToCameraDefault()`, never `ToCamera()`: tall furniture goes on the walls away from the default camera and joins its wall's group (it comes off with the wall in other views; a tall container hidden that way cannot be opened until the view is turned). Hearths stay.
  - Furniture is only kept if the door still leads to every container (`InteriorOk`); a container's `Stand` point is a free nav cell that later pieces may not cover.
  - Orthographic camera 120 m from the scene: no `MaxDrawDistance` on lights, no SkyAtmosphere aerial perspective (a blue dome at cinematic quality), exposure fixed in the PostProcessVolume. People cast no shadow at the engine's `r.Shadow.RadiusThreshold` (0.01 of the shadow frustum, which is sized by the camera distance): the generator lowers it in play (`ShadowRadiusThreshold`) and restores it in `EndPlay`.
  - Villagers (`AIVVillager`, models in `786`): spawned by each section in play only (`VillagerCoverage` x its buildings), moved along `FindPathEx` paths without doors (no movement component: the village is flat), one path search a frame for the whole village (`TakePathSlot`). They block her unless `bVillagersBlockPawns` is off (the Cine copy).
  - random_isometric_village_level_Cine (`783`-`785`, `787`): the generator follows `Demo_IV_Fem5` (`TrackedActor`, fixed seed, `TrackedAutoDoorDistance`); the sequence keys the view turns (camera yaw and the generator's `ViewYawOffset`); villagers are not on the sequence clock, so the reel's maps use `787`'s recording of the render itself; she stands while the big map is open, as in play; her mesh needs custom depth + stencil 1 (set by `783`; in play the controller sets it).
- **starship_level:** C++ `ASSFighter` / `ASSMissile` / `ASSArena` / `ASSTarget` / `ASSPlayerController` / `ASSHUD` / `ASSGameMode` / `USSFXLibrary` (`Source/claude_ue5/SS`); `800` then `801` build it (`800` without `fighter` clears the level, so `801` must follow).
  - The fighter is data: `Parts` (pack meshes in the ship frame, +X forward; `bFlame` parts stretch along the mesh's own Y with the throttle, `Rail` parts are the missiles on their rails), `CannonMuzzles`, `MissileRails`, `Thrusters`. It stands in the level and possesses itself (`ASSGameMode` has no default pawn). Pack-only by the user's choice: no modelled parts.
  - It has no collision of its own: each frame it sweeps a sphere against the *complex* collision of whatever is there (the pack meshes mostly have no simple collision), bolts and missiles line-trace the same way (`ECC_Visibility`). Static clutter needs `BlockAll`.
  - Destructible targets (asteroid fields, containers, drones) are spawned by the arena in play from its data and are never saved; the station and the big asteroids are level actors tagged `ss_clutter`. `KeepOut` spheres keep spawns out of them.
  - Effects: Mega_City's `NS_ship*` are *traffic* (they spawn whole ship meshes), not trails. No Niagara system can be authored from Python here.
  - The kit's planet materials shade themselves from a `Light_direction` parameter (toward the sun, world space), not from the level's lights: `800` makes instances with this level's sun.

A flight test that never flew through the gates did not notice they were shut: a path meant to be flown needs a test that flies it (805's `gate` events).
  - `800` puts the fighter at the start corner; `801` moves it onto the first gate's axis, facing it (from the corner, flying straight on met the first gate's rim after two seconds). `800 fighter` leaves it where it is. A test that respawns is in the gate course 2 s later: keep each check short, or count `collisions`, since a bounce turns the nose and spoils a measurement.

A packaged game starts on `GameDefaultMap`, and the installed engine cannot build a target with `CustomConfig` (it needs a unique build environment), so the script swaps `GameDefaultMap` / `GlobalDefaultGameMode` in `DefaultEngine.ini` for the run and restores the file in a `finally` (check `git status` if a run is killed). Verify a package with its own self test (`-RenderOffScreen -SSSelfTest=12`: report + picture), not with a desktop screenshot. Output goes to `builds/` (ignored: cooked pack content).
  - Demo reel (`804`-`806`, `ss_reel_overlay.py`): rendered on the playable level, `soft_game_mode_override` = `SSGameMode`, a sequence without tracks (the picture is the player's view; the fighter's `SetChaseCamera` / `SetWatchCamera` / `SnapCamera` do the camera work). The queue does not draw the HUD (the overlay does). ## Editor pitfalls

**Maps**
- Never `duplicate_asset` a map. Use `EditorLoadingAndSavingUtils.save_map` (Save As), then restart the editor (`unreal.SystemLibrary.quit_editor()` and relaunch) before opening the copy.
- Save As fails ("Unable to overwrite existing package") when the target map was loaded earlier in the session. Quit, move the old `.umap` out of `Content/`, relaunch and Save As again.
- Never reload the currently open map from Python.
- Before stopping PIE, wait a couple of seconds after `HighResShot`; once the editor asserted on `GameViewport.IsUnique()`.

**Blueprint DSL** (`editor_toolset` `write_graph_dsl`)
- `elif` nests as the last form of the previous branch.
- FText pins take no literals; enum pins take quoted names (`:Channel "ECC_Pawn"`).
- `Utilities|IsValid` is a macro with no bool output.
- One bad form leaves an empty graph. Read the graph back and check `LogScript: Warning` in the log.

**Asset edits**
- Struct arrays such as SkeletalMesh materials and BlendSpace samples are copies. Rebuild the whole array, call `modify()`, then `save_loaded_asset(..., only_if_is_dirty=False)` and verify after a reload.

**Retargeting**
- `add_default_ops()` leaves the Root Motion op without bones. Set root/pelvis yourself.
- Keep the template `CR_Mannequin_FootIK` alpha at 0 on UE4-style skeletons.
- CharacterMovement floats the capsule about 2.2 cm, so drop the mesh by that much.
- Tripo clips pin the hips; ground them per clip (FF2 scripts `275`–`289`).

**Materials**
- A TextureSample on an sRGB-off grayscale texture needs `SAMPLERTYPE_LINEAR_GRAYSCALE`. Otherwise the compile fails silently: `MaterialEditingLibrary.get_statistics(m).num_pixel_shader_instructions == 0`.
- The landscape grass mask (`383`) must be `never_stream` with no mipmaps. After changing it, run `grass.FlushCache`.

**castle_level**
- Run `340` before `380`.
- `340`'s traces skip pack foliage and props (`trace_to`).
- Interiors need their own capped-exposure PostProcessVolume.
- The scanned barrels (`SM_Scan_Barrel*`) render as a grey patchwork; use the pack's `SM_barrel_01/02`.

## Safety

- **No full-desktop screenshots:** one exposed private windows, including credentials. Verify visually with editor-viewport `HighResShot`, Movie Render Queue frames or `SceneCapture2D` (`pipeline/unreal/capture.py`) only.
- **Fab downloads:** acquiring or downloading Fab content needs the user in the Epic Games Launcher. Don't automate the launcher UI.

## Git

The remote (`github.com/beknar/claude-ue5`) is **public** and the repo is **source only**:
- Never commit `Content/`, `.uasset`/`.umap`, source-art binaries, media (`.png`, `.mp4`, …), archives, or `Saved/` / `Intermediate/` / `DerivedDataCache/`.
- Third-party packs (Fab, Megascans, MetaHuman, UE mannequins) must not be redistributed.
- `.gitignore` enforces this. Check `git status` before committing.
