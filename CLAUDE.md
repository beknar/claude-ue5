# CLAUDE.md

Guidance for Claude Code in this repository. See README.md for what the project is, what it can do (its Capabilities section) and how the levels were built.

## Goals

- **Everything is built by script.** A level, a character or an effect exists because a numbered script (or the C++ module plus the script that fills its data) builds it; nothing is arranged by hand in the editor. A change is finished when the script that makes it is in `pipeline/`.
- **Each world is a game, not a backdrop.** The newer levels are played: generated in play, with doors, containers, creatures, fighting, sound and music. A new feature for one of them comes with a step in that level's scripted test, and README's level table and rebuild notes say what it does.
- **A feature is shown in a demo reel.** When asked for a reel: the same kind as the level's earlier ones (45 s for the dungeon fight, 30 s for the fighter), rendered at 1080p, and delivered in two files in `renders/`: `<Name>_Showcase.mp4` and `<Name>_Showcase_20MB.mp4` (20 MB or less: `encode_video.py`'s `video_kbps` argument). Earlier reels are kept; a new one gets a new name.
- **Measured, not assumed.** A claim in a report is one a test, a recording or a rendered frame showed. A test must measure the thing itself, not a number that stands for it (a container's open value said nothing about where its lid was). What could not be checked is said so: nobody here hears a sound or watches a video, so sounds and music are chosen by name and measurement and verified by recordings.

## Conventions

- **Script names:** editor scripts are `pipeline/unreal/NNN_name.py`, numbered in build order. Each starts with a docstring giving its purpose and arguments. New stages get the next free number in their range (see README). `790`-`799` (random_dungeoncombat_level) is full, `800`-`806` is starship_level and `810`-`819` the two magic levels: further dungeon stages start at `820`.
- **One-off probes:** keep them out of `pipeline/` (use a scratch directory) unless they become a pipeline stage.
- **Idempotent:** scripts delete what they previously generated (by tag, label or asset path) and rebuild it. Spawned actors are tagged:
  - `castle_gen`: `340` (doors, floors, containers)
  - `castle_furn`: `380` (furniture)
  - sf-city-level: `sfc_road` (`703`), `sfc_struct` (`706`), `sfc_start` (`707`), `sfc_safety` (`708` barrier walls)
- **Cinematic copies:** each level has a `*_Cine` copy. Demo characters run on the Level Sequence clock (`SeqTime`/`DemoStartTime`), so Simulate (game time) and Movie Render Queue renders match.
- **Coordinates:**
  - UE = Blender (x, −y, z) for FBX round trips.
  - The furniture kit's front is UE +Y.
  - Kit sizes are in cm; the Blender scene uses `scale_length` 0.01.
- **End of big scripts:** delete the module globals and run `gc.collect()`. Lingering actor references caused python311 access violations on the next PIE start or map load. `ue_exec.py` now runs each script in a fresh namespace and clears it afterwards, also when the script raises (an exception's traceback otherwise keeps its actors alive). Scripts that leave a tick callback running must set `__keep__ = True` (their functions still need their globals) and drop their actor references when the callback finishes.
- **C++ module** (`claude_ue5/Source/claude_ue5`: `RT` town, `RD` dungeon and its combat / blood / sound, `IV` village, `SS` fighter): build with `pipeline\build_cpp.ps1` while the editor is closed, then relaunch. Unity builds merge the .cpp files: give file-local helpers and constants a module prefix (`IVPickSign`, `RDPickSign`, `IVCyan`, `SSGreen`), or adding a file can make two of them collide. No .NET Framework SDK is installed, so the script points UnrealBuildTool at a stand-in NETFXSDK (UE_SDKS_ROOT) for that build only. Python sees UPROPERTY bools without the `b` prefix (`bCollision` -> `collision`).

## Monster gallery (`docs/monsters.md`, `900`)

- The ranking is data (`SourceArt/monster_gallery/monsters.json`); `monster_doc.py` writes the page and the strips from it. Edit the JSON, not the page.
- **The user allowed committing the gallery's pictures** (`docs/images/monsters/*.jpg`: renders of pack models, not the models). The packs themselves, their textures and the Unity files unpacked into `SourceArt/fab_unity` stay local.
- **Shoot after the shaders are ready.** A `SceneCapture2D` loop inside one Python call cannot wait for anything: materials still compiling are drawn with the engine's grey checker placeholder, and textures with their low mips. That made most of the first gallery grey. `900` stages the monsters, then puts the variant material on every one (`warm`: each kind of skinned mesh needs its own shader permutation), and shoots in a later call with `r.TextureStreaming 0`.
- Python details:
  - `MaterialEditingLibrary.get_used_textures` takes a `Material` only; read an instance's own textures from `texture_parameter_values`.
  - A `SceneCaptureComponent2D`'s `show_only_actors` cannot be set from Python ("cannot be edited on templates"): use `show_only_actor_components`.
  - The scratch level is left empty and saved: a dirty level makes the next map load ask, and the editor waits for the answer.

## Vehicle gallery (`docs/vehicles.md`, `903`)

- The list, uses and descriptions are data (`SourceArt/vehicle_gallery/vehicles.json`); `vehicle_doc.py` writes the page, its sizes and animation notes come from `902`. Its pictures are allowed in git like the other galleries'.
- Models from 0.6 m to 115 m stand in one row: each gets a floor of its own, and every shot uses a show-only list (the model and its floor), or the neighbours fill the background. The camera distance is fitted to the model's box corners for the view direction; the "side" is the long side, unless `axis` says otherwise (the dragon's wingspan is longer than its body).
- **A long session of galleries ran the editor out of memory** (texture streaming off, hundreds of packs' textures loaded): it crashed staging the first vehicles. Restart the editor before a big gallery; after the restart the first `load_level` of the scratch level did not take for play-in-editor (PIE played the startup map): load it with `EditorLoadingAndSavingUtils.load_map` and check the PIE world's name.
- Right after play-in-editor stops, `get_editor_world()` can return None for a few seconds: a batch driver must wait for it before the next stage, check that play has started on the level it staged (`UEDPIE_0_<level>`) before shooting, and that it has stopped before staging again.
- **Never run two editors on the project.** After the crash a relaunch was checked with `-match "NODE"`, which (case-insensitive) matched ue_exec's `no remote nodes found`; a second editor was started, and remote commands went to either one: stages landed in one, play started in the other, batches shot nothing or the previous batch. Check `Get-Process UnrealEditor` before launching and test ue_exec's ping with `-cmatch "^NODE"`.

## Weapons and items gallery (`docs/objects.md`, `904`)

- The list, uses and descriptions are data (`SourceArt/object_gallery/objects.json`: `section`, `group`, `kind` for the third-person sets that hold it, `fp` for its first-person arm clips); `object_doc.py` writes the page. Its pictures are allowed in git like the other galleries'.
- An FPS pack's shot and reload clips are often on the bare gun's skeleton (`*_Basic`), not the full gun's: `904` uses a clip only if one of the entry's meshes is on its skeleton, otherwise the third picture is the far three-quarter view.
- **Armour** comes in pieces skinned to a character's skeleton; an armour set is all of one character's pieces (picked by name: armour, helmet, mask, crown, pads... never the bare body or arms under them) on one spot, an empty suit in the reference pose. Its note names the wearer (`wearer`). Armour sets carry full-size character textures: with texture streaming off, 8 sets in one batch ran a long-lived editor out of memory. Stage 4 at a time and restart the editor every 40 or so.
- The claims of the third-person table (`WIELD` in `object_doc.py`) were checked against `902`'s libraries: there are no third-person bow, crossbow, staff, knife or throwing clips for the UE4 mannequin here (the Dark Fantasy Weapons pack aims a bow and a crossbow on the UE5 mannequin). Check them again after importing animations.

## Hero and enemy galleries (`docs/heroes.md`, `docs/humanoid_enemies.md`, `901`, `902`)

- The lists, roles and descriptions are data (`SourceArt/hero_gallery/heroes.json`, `SourceArt/enemy_gallery/enemies.json`); `hero_doc.py` and `enemy_doc.py` write the pages. Their pictures are allowed in git like the monster gallery's. An enemy that is also a hero (`hero`) shows the hero's pictures and is not shot again.
- Each entry's animation note and the Animations section come from `902` (`SourceArt/character_animations/animations.json`: clips grouped by skeleton, each character's rig by its bone names) through `anim_text.py`; the Fab download's clips that were never imported come from `asset_survey/fab_animations.csv`. Re-run `902` after importing animations.
- **Framing an action pose:** a skeletal mesh's bounds in play are not where its posed body is: a crawl clip moves the root away from them, and some packs' bounds are far bigger than the body (the post-apocalypse zombie came out a speck). `901` frames the action shot on the bone positions (plus the weapon) whenever the bounds disagree with them.
- **Models of several meshes** (the crawlers: body, head, guts; a fish-man's shell): one actor per mesh, all on the same clip; a part on a skeleton of its own (Half Creature 01's eye) is left out of the posed copy, since the clip would not move it.
- **Action poses:** a one-frame AnimSequence made with the animation controller (`add_bone_curve`, `set_bone_track_keys`) on the hero's own skeleton: another pack's clip's local bone rotations at one frame, on the hero's bone lengths. It works between UE4-mannequin rigs (same bone names and axes); FF2's (Tripo) spell laid the body on the floor.
- **Pose frame:** the right frame differs per clip. An axe at its overhead wind-up turned the body away from the camera; a punch is the frame the fist is farthest forward, not farthest from the hips (the drunk man's swing then had the arms out like a T).
- **Where animations show:** the editor world does not evaluate a single-node animation on a `SkeletalMeshActor` (`set_update_animation_in_editor` did not help): stage in the editor, shoot during play-in-editor, which copies the staged actors.
- **Batch sizes:** with `r.TextureStreaming 0`, 100 staged characters ran the machine out of memory (the editor crashed) and 12 heavy ones hung the GPU (a D3D12 timeout, the editor stuck on an error dialog). Stage 6 to 10 at a time.
- After a crash the editor may stop on a **Restore Packages** dialog, which waits for an answer before remote execution comes up. `Saved/Autosaves/PackageRestoreData.json` lists the packages. Set it aside only if you know they are not wanted, as with a pack material that was never edited.

## Editor pitfalls

**Maps**
- Never `duplicate_asset` a map. Use `EditorLoadingAndSavingUtils.save_map` (Save As), then restart the editor (`unreal.SystemLibrary.quit_editor()` and relaunch) before opening the copy.
- Save As fails ("Unable to overwrite existing package") when the target map was loaded earlier in the session. Quit, move the old `.umap` out of `Content/`, relaunch and Save As again.
- Never reload the currently open map from Python.
- Before stopping PIE, wait a couple of seconds after `HighResShot`; once the editor asserted on `GameViewport.IsUnique()`.

**Blueprint DSL** (`editor_toolset` `write_graph_dsl`)
- `elif` nests as the last form of the previous branch.
- FText pins take no literals; enum pins take quoted names (`:Channel "ECC_Pawn"`).
- `Utilities|IsValid` is a macro with no bool output.
- One bad form leaves an empty graph. Read the graph back and check `LogScript: Warning` in the log.

**Asset edits**
- Struct arrays such as SkeletalMesh materials and BlendSpace samples are copies. Rebuild the whole array, call `modify()`, then `save_loaded_asset(..., only_if_is_dirty=False)` and verify after a reload.

**Retargeting**
- `add_default_ops()` leaves the Root Motion op without bones. Set root/pelvis yourself.
- Keep the template `CR_Mannequin_FootIK` alpha at 0 on UE4-style skeletons.
- CharacterMovement floats the capsule about 2.2 cm, so drop the mesh by that much.
- Tripo clips pin the hips; ground them per clip (FF2 scripts `275`–`289`).

**Materials**
- A TextureSample on an sRGB-off grayscale texture needs `SAMPLERTYPE_LINEAR_GRAYSCALE`. Otherwise the compile fails silently: `MaterialEditingLibrary.get_statistics(m).num_pixel_shader_instructions == 0`.
- The landscape grass mask (`383`) must be `never_stream` with no mipmaps. After changing it, run `grass.FlushCache`.

**castle_level**
- Run `340` before `380`.
- `340`'s traces skip pack foliage and props (`trace_to`).
- Interiors need their own capped-exposure PostProcessVolume.
- The scanned barrels (`SM_Scan_Barrel*`) render as a grey patchwork; use the pack's `SM_barrel_01/02`.

## Working rules

- **Commit and push only when the user asks.** Finished work stays uncommitted until then, and the report says so.
- **Leave the editor usable:** on a playable level (not a `*_Cine` copy), play stopped, started without `-deterministicaudio` (that switch is for a render with sound only; relaunch without it afterwards).
- **Scratch stays out of the repository:** probes, intermediate renders and test recordings go to the session's scratch directory.

## Safety

- **No full-desktop screenshots:** one exposed private windows, including credentials. Verify visually with editor-viewport `HighResShot`, Movie Render Queue frames or `SceneCapture2D` (`pipeline/unreal/capture.py`) only.
- **Fab downloads:** acquiring or downloading Fab content needs the user in the Epic Games Launcher. Don't automate the launcher UI.
- **System software:** installing anything on the machine (an SDK, a runtime, a codec) needs the user's go-ahead first.

## Git

The remote (`github.com/beknar/claude-ue5`) is **public** and the repo is **source only**:
- Never commit `Content/`, `.uasset`/`.umap`, source-art binaries, media (`.png`, `.mp4`, `.wav`, …), archives, `Saved/` / `Intermediate/` / `DerivedDataCache/`, `renders/` or `builds/` (a packaged game holds cooked pack content).
- Third-party packs (Fab, Megascans, MetaHuman, UE mannequins) and the sound and music library must not be redistributed. `SourceArt/random_dungeon_combat/audio/` (files converted from the library) is ignored; `sounds.json`, which only names the files, is committed.
- `.gitignore` enforces this. Check `git status` before committing: a new kind of generated file needs its ignore rule first.
- `ai models/*.glb` (the project's own Tripo characters, CC BY 4.0: `ai models/LICENSE` and `README.md`) is the one model exception: the user licensed them free to use. `old models/` (deprecated) stays ignored. The files were renamed: jrpg-fem5-tripo -> `Warrior.glb`, girl-caster-tripo -> `Mage.glb`, girl-darkcaster-tripo -> `Warlock.glb`; scripts, docs and Unreal assets keep the old names and tags (`Fem5`, `Caster`, `DarkCaster`).
- The galleries' pictures (`docs/images/monsters/*.jpg`, `docs/images/heroes/*.jpg`, `docs/images/enemies/*.jpg`, `docs/images/vehicles/*.jpg`, `docs/images/objects/*.jpg`) are allowed by the user, like the README's stills.
- Commit or push only when asked (see Working rules). Small data that a script reads or a test wrote (`SourceArt/**/*.json`) is committed; a test record replaces the one before it.
