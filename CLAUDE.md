## Conventions

- **Script names:** editor scripts are `pipeline/unreal/NNN_name.py`, numbered in build order. Each starts with a docstring giving its purpose and arguments. New stages get the next free number in their range (see README).
- **One-off probes:** keep them out of `pipeline/` (use a scratch directory) unless they become a pipeline stage.
- **Idempotent:** scripts delete what they previously generated (by tag, label or asset path) and rebuild it. Spawned actors are tagged:
  - `castle_gen`: `340` (doors, floors, containers)
  - `castle_furn`: `380` (furniture)
  - sf-city-level: `sfc_road` (`703`), `sfc_struct` (`706`), `sfc_start` (`707`), `sfc_safety` (`708` barrier walls)
- **Cinematic copies:** each level has a `*_Cine` copy. Demo characters run on the Level Sequence clock (`SeqTime`/`DemoStartTime`), so Simulate (game time) and Movie Render Queue renders match.
- **Coordinates:**
  - UE = Blender (x, −y, z) for FBX round trips.
  - The furniture kit's front is UE +Y.
  - Kit sizes are in cm; the Blender scene uses `scale_length` 0.01.
- **End of big scripts:** delete the module globals and run `gc.collect()`. Lingering actor references caused python311 access violations on the next PIE start or map load. `ue_exec.py` now runs each script in a fresh namespace and clears it afterwards, also when the script raises (an exception's traceback otherwise keeps its actors alive). Scripts that leave a tick callback running must set `__keep__ = True` (their functions still need their globals) and drop their actor references when the callback finishes.
- **C++ module** (`claude_ue5/Source/claude_ue5`, random_level's town generator): build with `pipeline\build_cpp.ps1` while the editor is closed, then relaunch. Unity builds merge the .cpp files: give file-local helpers a module prefix (`IVPickSign`, `RDPickSign`), or adding a file can make two of them collide. No .NET Framework SDK is installed, so the script points UnrealBuildTool at a stand-in NETFXSDK (UE_SDKS_ROOT) for that build only. Python sees UPROPERTY bools without the `b` prefix (`bCollision` -> `collision`).
- **random_level:** the town is generated by `ARTTownGenerator` (start square built in the editor by `752`, runtime cells never saved). Re-run `752` after changing templates or generator code. Docks building maps (`LI_Building_*`) cannot be opened while random_level is loaded (they are its level instances); `750`/`750b` open a scratch level first. `753` (generation indicator) rebuilds its materials in place and must be re-run on both random_level and random_level_Cine (each level's generator stores RevealDuration). In random_level_Cine the generator follows `Demo_RL_Fem5` (`TrackedActor`, fixed session seed).
- **random_dungeon_level:** C++ `ARDDungeonGenerator` / `ARDSection` (`Source/claude_ue5/RD`). Content is data: `770` fills the generator's `Pieces` map (each mesh normalised by `Adjust` to the dungeon frame: front +X, footprint centred, floor z 0) and the furnishing code places pieces by name, so a missing piece is skipped silently (check `770`'s piece list). Re-run `770` after C++ layout/furnishing changes (the start section is saved; play rebuilds only its doors, containers, monsters and map data from the same seed). Runtime sections are built over several frames (`FrameBudgetMs`). Every container must be openable (body + moving part); don't add closed barrels/crates/vases as static props. random_dungeon_level_Cine (`773`-`775`): the generator follows `Demo_RD_Fem5` (`TrackedActor`, fixed seed) and opens doors in front of her (`TrackedAutoDoorDistance`); monsters don't block her (`bMonstersBlockPawns` off).
- **random_isometric_village_level:** C++ `AIVVillageGenerator` / `AIVSection` / `AIVVillager` / `AIVPlayerController` / `AIVHUD` (`Source/claude_ue5/IV`).
  - The plan (ring streets, lanes, main roads, building sites) is a pure function of the plan seeds, so sections generated in any order continue the same village. Rings 0..4 and the bands between them use `StartSeed` (everything the start section touches); beyond that the session seed. A site's place and footprint come from the plan seed, what is built on it from the section seed.
  - Lane angles are not normalised: measure a block with `AngleSpan`, never with `A1 < A0`.
  - Content is data, as in the dungeon: `780` fills `Pieces` (House Forge kit pieces get explicit `Adjust` transforms: walls centred on their segment with the outside on +X, roofs cell-centred with the eave on +X); a missing piece is skipped silently. Re-run `780` after C++ plan / furnishing changes; it must report 0 unreachable doors / containers.
  - Each house keeps its roof, each of its four walls and each corner post in ISM components of their own (tags `IVG_<building>_<group>`: 0 roof, 1-4 the +X / -X / +Y / -Y wall, 5-8 corners). While she is inside, the roof and the walls facing the camera *as the view is turned now* are hidden (they still cast shadows and collide); its lights (tags `IVF_<building>`) are on only then. Changing the groups means re-running `780` and `783` (the saved start sections carry the tags).
  - The view turns (Q / E, `ViewYawOffset`), so anything decided at build time uses `ToCameraDefault()`, never `ToCamera()`: tall furniture goes on the walls away from the default camera and joins its wall's group (it comes off with the wall in other views; a tall container hidden that way cannot be opened until the view is turned). Hearths stay.
  - Furniture is only kept if the door still leads to every container (`InteriorOk`); a container's `Stand` point is a free nav cell that later pieces may not cover.
  - Orthographic camera 120 m from the scene: no `MaxDrawDistance` on lights, no SkyAtmosphere aerial perspective (a blue dome at cinematic quality), exposure fixed in the PostProcessVolume. People cast no shadow at the engine's `r.Shadow.RadiusThreshold` (0.01 of the shadow frustum, which is sized by the camera distance): the generator lowers it in play (`ShadowRadiusThreshold`) and restores it in `EndPlay`.
  - Villagers (`AIVVillager`, models in `786`): spawned by each section in play only (`VillagerCoverage` x its buildings), moved along `FindPathEx` paths without doors (no movement component: the village is flat), one path search a frame for the whole village (`TakePathSlot`). They block her unless `bVillagersBlockPawns` is off (the Cine copy).
  - random_isometric_village_level_Cine (`783`-`785`): the generator follows `Demo_IV_Fem5` (`TrackedActor`, fixed seed, `TrackedAutoDoorDistance`); her mesh needs custom depth + stencil 1 (set by `783`; in play the controller sets it).
- **Scripted PIE needs the editor unthrottled:** with the window in the background the editor drops to ~3 fps ("Use Less CPU when in Background", `config=EditorSettings`, a per-user global ini). `Config/DefaultEditorSettings.ini` turns it off for this project only.
- **MRQ warm-up runs at every camera cut:** world time advances while the sequence is frozen, so a demo character steered on the sequence clock stops and restarts at each cut, and time-based effects jump ahead. Shoot runtime-driven scenes as one camera cut (random_level's `756`).
- **sf-city-level safety:** after changing anything walkable, re-run `708` (flood fill + barrier walls) and check it reports 0 remaining fall edges; the walk test (`709` plan, `710` in PIE) reports clipping, falls, doors and stuck legs.

## Editor pitfalls

**Maps**
- Never `duplicate_asset` a map. Use `EditorLoadingAndSavingUtils.save_map` (Save As), then restart the editor (`unreal.SystemLibrary.quit_editor()` and relaunch) before opening the copy.
- Save As fails ("Unable to overwrite existing package") when the target map was loaded earlier in the session. Quit, move the old `.umap` out of `Content/`, relaunch and Save As again.
- Never reload the currently open map from Python.
- Before stopping PIE, wait a couple of seconds after `HighResShot`; once the editor asserted on `GameViewport.IsUnique()`.

**Blueprint DSL** (`editor_toolset` `write_graph_dsl`)
- `elif` nests as the last form of the previous branch.
- FText pins take no literals; enum pins take quoted names (`:Channel "ECC_Pawn"`).
- `Utilities|IsValid` is a macro with no bool output.
- One bad form leaves an empty graph. Read the graph back and check `LogScript: Warning` in the log.

**Asset edits**
- Struct arrays such as SkeletalMesh materials and BlendSpace samples are copies. Rebuild the whole array, call `modify()`, then `save_loaded_asset(..., only_if_is_dirty=False)` and verify after a reload.

**Retargeting**
- `add_default_ops()` leaves the Root Motion op without bones. Set root/pelvis yourself.
- Keep the template `CR_Mannequin_FootIK` alpha at 0 on UE4-style skeletons.
- CharacterMovement floats the capsule about 2.2 cm, so drop the mesh by that much.
- Tripo clips pin the hips; ground them per clip (FF2 scripts `275`–`289`).

**Materials**
- A TextureSample on an sRGB-off grayscale texture needs `SAMPLERTYPE_LINEAR_GRAYSCALE`. Otherwise the compile fails silently: `MaterialEditingLibrary.get_statistics(m).num_pixel_shader_instructions == 0`.
- The landscape grass mask (`383`) must be `never_stream` with no mipmaps. After changing it, run `grass.FlushCache`.

**castle_level**
- Run `340` before `380`.
- `340`'s traces skip pack foliage and props (`trace_to`).
- Interiors need their own capped-exposure PostProcessVolume.
- The scanned barrels (`SM_Scan_Barrel*`) render as a grey patchwork; use the pack's `SM_barrel_01/02`.

## Safety

- **No full-desktop screenshots:** one exposed private windows, including credentials. Verify visually with editor-viewport `HighResShot`, Movie Render Queue frames or `SceneCapture2D` (`pipeline/unreal/capture.py`) only.
- **Fab downloads:** acquiring or downloading Fab content needs the user in the Epic Games Launcher. Don't automate the launcher UI.

## Git

The remote (`github.com/beknar/claude-ue5`) is **public** and the repo is **source only**:
- Never commit `Content/`, `.uasset`/`.umap`, source-art binaries, media (`.png`, `.mp4`, …), archives, or `Saved/` / `Intermediate/` / `DerivedDataCache/`.
- Third-party packs (Fab, Megascans, MetaHuman, UE mannequins) must not be redistributed.
- `.gitignore` enforces this. Check `git status` before committing.
